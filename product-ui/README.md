# product-ui

Редизайн карточки товара (`/tproduct/...`). Работает с обоими блоками Tilda: новый каталог `t-catalog__` (тестовая /122222) и старый магазин `t-store__` (боевой /catalog); всё делается только в колонке товара, «Также вам может понравиться» не трогаем. Цвета-кружки остаются штатными: крупные заголовок и цена, «Оформление» карточками с фото, «Размер» кнопками с ценой, широкая кнопка покупки (на мобиле липкая), преимущества под кнопкой. Описание товара скрыто, вместо него блок «Как выглядят размеры».

CSS подтягивается скриптом сам, из той же папки. Картинки вариантов — модуль option-images (класс `dv-optimg-on`).

Цены в кнопках размера берутся из описания товара, строки вида `S 25 шт. — 450 AED`. Тексты преимуществ и ссылка на каталог — в начале `dv-product-ui.js` (`PERKS`, `CATALOG`).

## Допы в карточке

Скрипт сам подгружает модуль [addons](../addons/) из того же тега: полка «Дополните подарок» в карточке, попап после «В корзину», блок в корзине. Полка переставляется после опций, перед количеством/кнопкой «В корзину»; перекрашена в стиль карточки (3 в ряд, на мобиле лента со свайпом), ссылка «Добавьте шары…» скрыта. Если addons подключён отдельно, второй раз не грузится; отключить: `window.DV_ADDONS_SKIP = true`.

## Как выглядят размеры

Плашка под кнопкой покупки: превью `img/sizes.jpg`, по клику фото открывается на весь экран (закрыть — клик или Esc). Показывается только у товаров с опцией «Размер».

Своё фото или отключение — до подключения скрипта:

```js
window.DV_SIZE_GUIDE = false; // или { title, text, img: 'https://...' }
```

## Тест на боевом сайте

«Настройки сайта → Вставка кода → перед `</body>`» (стоит на сайте с 30.10.2026, больше не трогаем). Работает только на странице с `?dvui=1` в адресе, без запоминания. Всё остальное меняется в `dv-product-ui.js` и выкатывается новым тегом.

```html
<script>
(function () {
  // только когда в адресе есть ?dvui=1, без запоминания
  if (!/[?&]dvui=1(&|$)/.test(location.search)) return;
  // последний тег репозитория: при релизе ссылку в Tilda не меняем
  var repo = 'https://cdn.jsdelivr.net/gh/mirowdav/dejavu-tilda@';
  function load(v) {
    var s = document.createElement('script');
    s.src = repo + v + '/product-ui/dv-product-ui.js';
    (document.body || document.head).appendChild(s);
  }
  fetch('https://data.jsdelivr.com/v1/packages/gh/mirowdav/dejavu-tilda/resolved?specifier=latest')
    .then(function (r) { return r.json(); })
    .then(function (d) { load(d.version); })
    .catch(function () { load('v0.1.9'); });
})();
</script>
```

Скрипт при старте сверяет свою версию с последней в обход кэша браузера (браузер держит ответ API до часа и после релиза подсовывает старый тег) и, если отстал, грузит вместо себя актуальную. Загрузчик берёт последний тег репозитория через API jsDelivr (на практике новый тег доходит до сайта за ~5–7 минут после пуша), поэтому релиз = новый тег, Tilda не трогаем. Ссылка на тег у jsDelivr не устаревает, в отличие от `@main` (тот кэшируется до 12 часов, сброс расходится по серверам минутами, браузер держит файл до 7 дней). Теги общие на весь репозиторий: «последний» — самый старший по номеру. Сразу после пуша тега файлы с CDN не запрашивать — jsDelivr может закэшировать 404; лечится purge по тегу.

Локальная проверка: `before.html` / `after.html` (копии страницы, в git не входят).
